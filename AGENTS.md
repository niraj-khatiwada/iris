# AGENTS.md

Guidelines for coding agents working on Iris.

## Commands

```bash
bun install                 # Install dependencies
bun run tauri:dev           # Native app + Vite on port 3002
bun run vite:dev            # Frontend only, browser preview
bun run tauri:build         # Production bundle
bun run tsc:check           # TypeScript 7 native compiler
bun run lint                # Biome
bun run lint:fix            # Biome auto-fix
bunx shadcn@latest add …    # Add an islandcn registry item
cd src-tauri && cargo check # Rust
cd src-tauri && cargo clippy
```

Pre-commit (Husky) runs `lint-staged` (Biome) and `tsc:check`.

## Architecture

- `src/components/` contains reusable UI: design-system wrappers and chat pieces.
- `src/components/dynamic-island/` is the app-owned island integration. `DynamicIsland` wraps the whole app with the island provider (the visible pill is temporarily hidden) and is mounted once in `src/main.tsx`.
- `src/components/islandcn/` and `src/lib/island/` are vendored islandcn files. Do not edit them; add kit pieces through the shadcn registry.
- `src/ui/` composes screens. `src/routes/` stays thin.
- `overlay.html` + `src/overlay.tsx` are the quick-chat window. Its UI lives in `src/ui/Overlay`; there is no router, sidebar, or Dynamic Island in that window.
- `canvas.html` + `src/canvas.tsx` are the full-screen, transparent, click-through canvas. It is deliberately empty and must not receive interaction; it is the future surface for annotations and agent output.
- `src/hooks/useOverlayWindow.ts` owns the overlay's native behaviour: size to the panel, reveal after the webview has painted, focus, and hide on Escape or an explicit action. Do not add blur-to-dismiss.
- Rust window management for the overlay and canvas is `src-tauri/src/sys/overlay.rs`; its commands are `src-tauri/src/tauri_commands/overlay.rs`. Both are converted to non-activating NSPanels with `tauri-nspanel`, so summoning Iris never activates the app, focuses the history window, or switches Spaces. Use panel show/hide, not `window.set_focus()`.
- `src/stores/` is Zustand only. Use selectors (`useChatStore((state) => state.x)`), never whole-store subscriptions.
- `src/tauri/commands/` contains typed `invoke` wrappers, one file per Rust command module. Tauri snake_case args are passed in camelCase from TypeScript.
- `src/services/` owns transport concerns. The UI never talks to the agent transport directly; the browser preview mock is there too.
- DeepSeek settings live in `src/stores/settingsStore.ts`: base URL, model, system prompt, auto-speak, thinking effort, and TTS voice. **Iris is DeepSeek-only.** There is no provider picker, API-format switch, capability probe, or separate speech/transcription URL: `core/endpoints.rs` derives `/anthropic/v1/messages`, `/anthropic/v1/files`, `/v1/models`, `/v1/tools/tts`, and `/v1/tools/asr` from the base URL, which defaults to `https://api.deepseek.com` and only changes for a DeepSeek-compatible proxy. The Messages route is under `/anthropic`; the root `/v1/messages` returns 404. Thinking is always enabled; the composer's `ThinkingEffort` chip (`thinkingEffort`, default `low`) cycles through `low`, `high`, and `max` and sets `output_config.effort` to match. `deepseek_web_search` is always declared and the model decides whether to search; any link in the newest user message also adds `deepseek_read_url`. DeepSeek's server tools cannot be mixed with other server tools. Settings → AI Prompts → System prompts has separate `islandSystemPrompt` and `mainSystemPrompt` fields; `mainUsesIslandPrompt` defaults on and makes the main chat reuse the island prompt. `runAssistantReply` sends the island prompt from the overlay window and the main prompt (or the shared island prompt) elsewhere, as `systemPrompt`; `core/agent.rs` falls back to `SYSTEM_PROMPT` when it is empty. The compressed summary is appended to whichever prompt is used. **The API key is never in the store**: it lives in the SQLite `credential` table (plain text) behind `src-tauri/src/tauri_commands/credentials.rs`, and the webview only ever learns `{ hint }` from `save_api_key`. Never add a command that reads the key back to the UI. The last-four hint is cached in `settingsStore.apiKeyHint` (localStorage) so the saved state is instant; once saved the field is gone and only Replace and Remove are offered. `send_message`, `upload_document`, `list_models`, `speak_text`, and `transcribe_audio` read the key in Rust through `Storage::require_api_key`.
- Rust: `core/` for domain logic, `sys/` for platform helpers, `tauri_commands/` for command entry points, `utils/` for shared helpers.
- Keep the agent event contract (`chat:token`, `chat:thinking`, `chat:sources`, `chat:done`, `chat:error`) stable. The DeepSeek protocol lives in `src-tauri/src/core/agent.rs`; automatic TTS lives in `src-tauri/src/sys/speech.rs`. Thinking and web results are part of the transcript, not the reply. `core/agent.rs` reads `thinking` blocks as `chat:thinking` and `web_search_tool_result` / `web_fetch_tool_result` blocks as `chat:sources`; `chatStore` accumulates the reasoning on the streaming assistant message, then persists it to `metadata.thinking` when the reply completes, beside `thinking_effort` and deduplicated `metadata.sources` (capped at 30). History renders a collapsible **Thinking** panel above the reply, open while the model reasons and tucked away once text starts, plus a compact **Sources** pill under the reply. The quick overlay only shows a one-line **Thinking · <effort>** indicator while it waits for the first text token and still hides the reply until **Show response**. Reasoning is never copied, spoken, or sent back to the model, and the sources pill never appears in the overlay or read-aloud. A reply stopped while it already had text is kept and marked `metadata.stopped`, shown as **Stopped** in History and the overlay; a reply that hits `max_tokens` is reported as an error instead of looking complete.
- `core/agent.rs` compresses long conversations before sending: once a conversation passes `CONTEXT_BUDGET_CHARS`, older turns are folded into a summary (cached per conversation in `SummaryCache`) while the newest `RECENT_BUDGET_CHARS` stay verbatim. The summary is injected into the system prompt, so the visible history and SQLite rows are never rewritten.
- Every quick-overlay chat is a normal UUID conversation. `chatStore.quickConversationId` is the one the overlay is showing, persisted in SQLite's `app_meta` table (`quick-conversation`) so the overlay and history window agree. Double-clicking the conversation title in the overlay header flushes the overlay's pending writes and opens History on that quick chat; the mascot is a non-interactive status indicator. The two webviews synchronize through the shared `iris.chat.ui` selection and a `history:open-conversation` event, because they do not share a Zustand store. `ensureQuickConversation` opens the stored chat or creates a UUID; `resetQuickConversation` starts a new UUID and leaves a non-empty previous chat in History with its files. New chat also flushes pending writes and runs `delete_empty_conversations`, a database-confirmed cleanup of unarchived conversations with no messages; it keeps the new chat, the History window's active chat, archived chats, and every conversation with real messages. The backend emits `conversations:deleted` so both webviews drop the removed rows and the storage mirror cannot save them again. `restorePreviousQuickConversation` only toggles `quickConversationId` and `lastQuickConversationId`; it never moves messages or folders. The old fixed `iris:quick` row and its attachment folder are migrated once in `Storage::open`.
- The overlay header's **Search conversations** button opens a compact `ConversationSwitcher` above the composer. The **Search conversations** overlay shortcut (`⌘F` by default, configurable in Settings → Shortcuts) opens it too and refocuses the field when it is already open. It searches non-archived titles only (the 8 most recent, or up to 20 matches), excludes the current chat, grows the panel upward, and hides the response while open. A second click or Escape closes it without hiding Iris; arrows move, Enter opens, and the active row scrolls into view. Choosing a chat awaits `flushChatStorage()`, cancels the active run, calls `openQuickConversation`, settles the previous chat into History, keeps it as `lastQuickConversationId` for **Previous conversation** (`⌘⇧N`), loads the newest message page, and persists the chosen id. There is no schema change and no message-body search.
- Attachments enter through paste or drag-and-drop only; there is intentionally no attach button. The overlay and main windows set `dragDropEnabled: false` so Tauri's native file-drop handler does not swallow HTML5 drops, and files with no MIME type are recognized by extension. `useAttachments` stores originals under `<app data>/attachments/<conversation id>/` and adds a resized JPEG preview for images (max 4 images, 12 MB input). Documents are uploaded through Rust to DeepSeek's `/anthropic/v1/files` (max 32 MB for `user_data`, 100 MB for parsed PDF/Word/PowerPoint, at most 20 documents per draft, three concurrent uploads). Plain text, Markdown, code, spreadsheets, and ebooks use `user_data`; PDF, DOC/DOCX, and PPT/PPTX use `rich_layout_recognition`. Messages store `fileName`/`previewName` for local files and `fileId`/`purpose` for documents; new images have no data URL in SQLite, while legacy inline images remain supported. `AttachmentStrip` shows image thumbnails and document cards with upload/retry state. The Rust agent reads image preview files from the conversation folder, emits `document` blocks for file ids, and adds `anthropic-beta: files-api-2025-04-14` when a request contains a document. Message images use the Tauri asset protocol (`$APPDATA/attachments/**` scope); double-clicking opens the full-screen `preview` panel, and the hover/download action saves a copy via the dialog. Permanent conversation deletion, Clear, Reset, and deleted messages remove the corresponding local files; archiving keeps them. Quick chats use their own UUID folders, so deleting them removes exactly their files, and summaries ignore attachments.

## Code style

### TypeScript / React

- Biome: 2 spaces, 80 columns, single quotes, double quotes in JSX, no semicolons, trailing commas.
- Imports: node → packages → `@/` alias → relative. Biome organizes imports on save.
- Use `@/` for `src/`.
- Components are folder-per-component with an `index.tsx` (or a named file inside the folder). Export the component as default and set `displayName`.
- Use function declarations; React 19 ref-as-prop is fine.
- Prefer HeroUI v3 primitives and the wrappers in `src/components/` over raw HTML controls. The composer textarea is intentionally a HeroUI `TextArea`.
- Use `cn()` from `@/utils/tailwind` for class merging.
- Styling: Tailwind v4 utilities and HeroUI semantic tokens (`bg-background`, `bg-surface`, `text-muted`, `border-border`, `bg-accent-soft`). Avoid hard-coded palette colors.
- No translations in this project. User-facing copy is English.
- No `console.log`; use `log_error` from Rust or surface errors in the UI.

### Zustand

```typescript
export const useThingStore = create<ThingState>()(
  persist(
    (set, get) => ({
      value: 0,
      setValue: (value) => set({ value }),
    }),
    { name: 'iris.thing' },
  ),
)
```

- Read with selectors. Write with actions.
- Persist only durable data. Streaming flags and transient UI state stay out of storage. SQLite is the only conversation store; localStorage holds settings and the two selected conversation ids (`iris.chat.ui`). Never put conversations back into localStorage.
- Sanitize persisted data in `merge` if its shape can go stale (see `chatStore`).

### Rust

- snake_case files and functions, PascalCase types, SCREAMING_SNAKE_CASE constants.
- Commands return `Result<T, String>` and use `#[tauri::command]`.
- Serialize payloads with `#[serde(rename_all = "camelCase")]` to match TypeScript.
- Keep blocking work off the main thread; use `tauri::async_runtime::spawn`.

## Notifications and the Dynamic Island

- The dynamic island is the app's notification surface. Use `useDynamicIslandNotice()` from `@/components/dynamic-island/notifications`; never add Sonner, Radix Toast, or a custom toast stack.
- The main window currently hides the island pill to keep the top bar clear. Its provider stays mounted so notices and activities are ready when the pill returns; do not add a second notification system in the meantime.
- Agent activity is already wired in `src/components/dynamic-island/agent-activity.tsx`: it follows `streamingRequestId` from the chat store, shows elapsed time and Stop when expanded, and alerts once on failure.
- Build new activities beside the feature that owns them, on the island engine (`useIslandActions` / `useActivity`). Do not install a preset unless it is an exact match.
- Keep the pill pure black. Use the island's content kit (`src/components/islandcn`) for glyphs, text, rings, buttons, and layout so it matches the reference hardware.
- `components.json` is required for the shadcn registry aliases (`@/lib`, `@/components`, `@/utils/tailwind`).
- To add a kit piece: `bunx shadcn@latest add https://islandcn.dev/r/<item>.json`. Files land in `src/components/islandcn`; do not hand-write replacements.
- Biome ignores `src/lib/island/**` and `src/components/islandcn/**` on purpose. Keep vendored code byte-for-byte close to the registry.

## UI conventions

- Dark is the default theme. Respect light and system modes through the existing `useThemeSync` hook.
- The palette uses one primary color (`--primary`) for the AI blob, success feedback, and HeroUI's accent. The avatar's body colour overrides `--primary` app-wide (`applyAccent`); an empty avatar colour falls back to the Iris green default. Surfaces stay neutral glass; do not reintroduce colored auroras, colored glass tints, or broad gradients.
- The main window uses an overlay title bar. The sidebar and chat headers sit at the very top and carry `data-tauri-drag-region`; the sidebar header keeps its left side empty for the macOS traffic lights. The open sidebar has no collapse button: drag its right border to resize it between 220 and 420 px (the settled width is persisted as `sidebarWidth` in settings), and double-click that border to toggle it between open and collapsed; the collapsed rail's expand button also works.
- The dynamic island is hidden for now. Keep the top centre free of app chrome until it returns.
- Pressing `/` focuses the composer when focus is not already in a text field. The quick overlay and the history window both support this. `Cmd+Shift+F` (configurable in Settings → Shortcuts) expands the sidebar and focuses its search field; search covers conversation titles and message bodies through SQLite FTS5. The overlay's local shortcuts are configurable in Settings → Shortcuts: **Capture screen** (`⌘⇧S`), **Search conversations** (`⌘F`), **New chat** (`⌘N`), **Previous conversation** (`⌘⇧N`), **Show / hide response** (`⌘B`), **Voice input** (`⌘I`), and **Stop read-aloud** (`⌘X`). `Cmd+,` still opens Settings. `sys/menu.rs` removes macOS's Close Window (`⌘W`) menu accelerator so it cannot dismiss the overlay; the history window handles `⌘W` itself with `hide_main_window` and hides exactly like its red close button. The overlay intercepts the Copy event if Capture is rebound to `⌘C`. `useStopSpeakingShortcut` catches the Cut event while read-aloud is active, and the stop binding only claims `⌘X` while speech is preparing or playing so Cut keeps working otherwise.
- **Ask about selection** is a second global shortcut (`selectionShortcut`, default `⌘⇧Space`) configured in Settings → Shortcuts. `sys/selection.rs` reads `AXSelectedText` from the frontmost app's focused element (falling back to system-wide focus and rejecting only Iris's own pid, because browser web content lives in a renderer process), falls back to a temporary ⌘C when Accessibility exposes nothing (and detects an unchanged pasteboard so the old clipboard is never mistaken for a selection), rejects `AXSecureTextField`/`AXSecureTextArea`, and stores the source app pid for `replace_selection`. The trigger hides the overlay before reading, so a visible Iris panel cannot stay the key window. When Accessibility cannot inspect the focused field, Iris now uses the temporary ⌘C fallback in every app, including T3 Code and other Chromium/Electron apps whose web content lives in a renderer process. The overlay's `SelectionPanel` sends a new quick chat with the selected text as a title seed; **Custom** closes the strip into that chat with a selection chip, and typing or voice composes an instruction that is combined with the selected text. Copy, **Paste**, and **Replace selection** use the result: Paste inserts at the source app's focused caret through the clipboard and ⌘V, while Replace overwrites the captured selection. The response footer order is Copy, Read aloud, Regenerate, Paste, Replace. Automatic read-aloud for selection results is controlled separately by `settingsStore.autoSpeakSelection` (default off) and still requires the global `autoSpeak`; the manual Read aloud button always works. `save_selection_metadata` records the source app, bundle id, pid, action, and selection stats in `selection_metadata` against the user message. Accessibility permission is required; the error strip opens System Settings. Secure fields are rejected whenever Accessibility identifies them, and macOS blocks copying from standard secure fields; never write a secure field through AX. Escape cancels the selection strip and returns to the normal composer without hiding Iris; the header X still hides the overlay. All AppKit window and pasteboard work must go through `on_main`; the Tokio selection task must not call `overlay::show` directly (it traps inside `NSWMWindowCoordinator`).
- **Ask about screen** is a third global shortcut (`screenAskShortcut`, default `⌘⇧A`) configured in Settings → Shortcuts. `capture_screen_for_ask` captures the whole display under the mouse at native size as a JPEG, hides Iris during the shot, restores the overlay, and emits the existing `capture:attached` event into the current quick chat. It focuses the prompt but never auto-sends. There is no capture panel, region selection, annotation, window picker, or new endpoint; `⌘⇧S` remains the region/annotation path. Permission and errors reuse the existing Screen Recording notice.
- Selection prompts and **Custom** preserve any draft attachments, including a screen capture from `⌘⇧A` or `⌘⇧S`. If the draft has attachments, Iris keeps the current quick chat so the files stay in the same conversation folder and sends them with the prompt; it only resets to a fresh quick chat when the draft is empty. `/` quick prompts already send the current attachments.
- Quick prompts live in `settingsStore.quickPrompts` and are edited at Settings → AI Prompts. The built-in defaults keep the old selection-action ids plus `simplify`; users can add, rename, delete, pick an icon, and drag to reorder. Each built-in instruction ends with the house style rule `Do not use em-dash, use ";" instead of em-dash.`; schema-3 migration appends it to existing built-ins, while user-created prompts are never modified. The same order drives the overlay's selection strip and the `/` menu in both composers. Choosing a `/` prompt attaches a pending chip; the typed text is stored as the user message while `sendMessage(..., requestPrompt)` wraps it for the model only. With an attachment in the draft and an empty composer, the quick prompt itself is the request: Enter sends it, and `buildSelectionPrompt` omits the empty `<selected_text>` block. Changing conversations, New chat, Cancel, or selecting a selection action clears the pending prompt. The `/` menu only stays open while the text after the slash has no whitespace and at least one prompt matches; otherwise the slash is ordinary text and no empty-state UI is shown. Matching uses the prompt name only; the instruction is never searched.
- **The quick overlay is the primary interface.** Keep it to one bottom input, Iris's status, and a single response block. No sidebar, no message bubbles, no user-message echo, no chat transcript. The response block ends with Copy, Read aloud, and (for the newest reply) Regenerate actions; never put Copy in the header.
- The Iris blob is the only status indicator. Primary green plus the `IRIS` label means ready (no `Ready` text, no status dot). Amber means a request is in flight; blue means read-aloud is preparing or playing (the wave is blue while speaking); red means an error. No spinner, play badge, or progress labels: only color and error text.
- Processing is voice-first: show the blob/ring/wave effect and only **Cancel**; never render the reply while streaming or by default after completion. The small **Show response** control reveals it on demand.
- Voice input lives in the quick overlay. The mic records 16 kHz mono WAV and Rust posts it to `/v1/tools/asr`. `autoSendVoice` defaults on; when off, the transcript goes into the input. While the voice strip is open, Enter stops and sends (even when auto-send is off) and Escape cancels the recording without hiding Iris. Overlay hide must cancel recording. `speech:start` / `speech:end` carry the conversation id and drive the speaking strip; use the blob's `listening` and `speaking` activities.
- Do not auto-dismiss on focus loss. The overlay stays until Escape, the close button, the shortcut, History, or Quit.
- The full-screen canvas is click-through and non-focusable. Do not put buttons or interactive UI on it; the input panel is a separate window above it. It draws the transient overlay snap guides and is the future surface for annotations and agent output.
- Animate state changes with `motion` springs; do not swap layouts abruptly. The native window height follows the animated panel height through the ResizeObserver.
- The overlay is dark by default but follows the macOS appearance (not the in-app theme setting):
  light glass with dark ink when the system is in light mode. It sits above other windows and on
  every workspace. It must **not** dismiss on focus loss: hide only on Escape, the close button,
  the shortcut, or an explicit action.
- The history window is secondary. It exists for old conversations and the Dynamic Island; do not redesign it until asked.
- The chat UI is provisional: **do not add new screens or redesign the chat** until the user provides the new UI direction.
- The assistant's identity is the Iris avatar (`src/components/IrisBlob`, powered by the `bot-avatars` package), not a generic avatar. `IrisBlob` keeps the emotion/activity API (`listening`, `speaking`, `thinking`, `happy`, `sad`) and maps it onto the library's `default`, `working`, and `sleeping` states. The saved look (body type, colour, face, material, accessories) lives in `settingsStore.avatar` and is edited in Settings → About; tone and emotion still come from the app state, and the body colour also becomes the app-wide `--primary` accent. The old SVG engine is preserved under `src/components/legacy/AiBotAvatar`.
- Keep animations subtle and honor `prefers-reduced-motion`; `bot-avatars` already does.
- Glass is part of the design language. Reuse `.liquid-glass` for dark floating surfaces, and `.glass-rail`, `.glass-control`, and `.glass-dialog` for theme-aware surfaces. Do not replace them with flat solid fills.
- Cursors follow native macOS: only `a[href]` (and `[data-link]`) show the pointer. Buttons, tabs, toggles, and other controls keep the arrow via `--cursor-interactive: default`, `--cursor-disabled: default`, and the `[class*="cursor-pointer"]` override in `global.css`. Do not add `cursor-pointer` to app controls.
- The sidebar follows one rhythm: an 8px rail inset (`px-2`) for the search field, New chat button, and conversation list, 12px content inset (`pl-3`), 36px row height, 14px icons, and 13px labels. Conversation rows reserve 36px on the right (`pr-9`) for the hover actions. Keep new sidebar items on these values instead of inventing spacing. The top of the sidebar is one row: a `.glass-control` search field with an icon-only glass New chat button at its end. The leading search glyph becomes a clear button once the query has text. While the search has text, the grouped conversation list is replaced by title matches and message snippets grouped by conversation. The open footer shows an `API key is not set` shortcut with an arrow when no credential is stored; it opens Settings → API Key directly. The footer rechecks `has_api_key` on mount so a stale cached flag cannot hide the prompt. The collapsed rail shows only the sidebar toggle, New chat, and search icons on the 8px rhythm; it never renders conversation icons.
- Inputs are intentionally quiet: no focus ring, outline, glow, or accent border on focus. Keep the caret as the only focus cue. Do not reintroduce HeroUI focus rings on text fields. Text fields spread `NO_WRITING_ASSIST` (`spellCheck={false}`, `autoCorrect="off"`, `autoCapitalize="none"`) and every HTML entry point sets `spellcheck="false"`, so macOS spelling and autocorrection bubbles never cover Iris.

## Project conventions

- Bun is the package manager. Commit `bun.lock`.
- Release builds use `lto = "thin"` and `strip = "debuginfo"` in `src-tauri/Cargo.toml`, with `[profile.release.build-override] strip = "none"` for proc-macro host artifacts. Do not remove that override: `thiserror 1`'s proc macro then fails with `can't find crate for thiserror_impl`. Do not restore `lto = true` with `strip = true`: that combination makes Rust unable to load proc-macro dylibs (`include_dir_macros`, `tauri_macros`) and fails with "can't find crate for ...".
- Dev server port is **3002** (3001 belongs to CompressO).
- No test framework configured yet. Do not invent test scripts.
- `src/routeTree.gen.ts` is generated by TanStack Router; do not hand-edit it.
- Tauri icons live in `src-tauri/icons/`. The app icon is drawn in `assets/app-icon.svg`; regenerate the set with `bunx tauri icon assets/app-icon.svg` and remove the generated `android/` and `ios/` folders. The menu bar tray icon source is `assets/tray-icon.svg`.
- `components.json` points shadcn at our aliases and `src/global.css`.
- Window labels are `overlay` (quick chat), `canvas` (full-screen transparent surface), `capture` (screen selection and annotation), `preview` (full-screen image lightbox), and `main` (history). Keep them in sync across `tauri.conf.json`, capabilities, and Rust. The canvas, capture, overlay, and preview windows must stay `alwaysOnTop`, `visibleOnAllWorkspaces`, and at AppKit levels 25/26/27/28.
- The summon shortcut is configurable in Settings → Shortcuts (`openShortcut` in `settingsStore`). Rust registers `commandorcontrol+space` at startup, then `set_open_shortcut` replaces it with the recorded choice. If the overlay is hidden it opens and focuses; if it is visible but not focused it focuses; only a focused overlay closes on the next press. Every show/focus restores the webview first responder and emits `overlay:focused`; `useOverlayWindow` then focuses the quick-chat input and puts the caret at the end. Escape closes it. There is no frontend shortcut plugin.
- A menu bar tray icon (`src-tauri/icons/tray.png`, generated from `assets/tray-icon.svg`) is the fast access point: left-click toggles the quick overlay (visible hides, hidden shows) without opening a menu; right-click opens the **Ask Iris**, **History**, and **Quit Iris** menu. `RunEvent::ExitRequested` is prevented only while both windows are hidden; the menu bar's Quit always quits.
- The overlay is CSS glass only. Do not apply a window-level native material to the overlay: it adds a second square window edge around the rounded card. Keep the transparent shadow gutter and the single `.liquid-glass` panel.
- The overlay is draggable by its header and input-row background (`data-tauri-drag-region="deep"`). While dragging, `sys/overlay.rs` emits `overlay:guides`; the full-screen canvas draws two dashed lines at the centered panel's edges, and they turn primary green when the window center is within 24 px of the display center, where the window snaps horizontally. `sys/overlay.rs` keeps the bottom edge fixed while the panel resizes, saves the frame to `overlay-position.json` in the app data directory, restores it on the next show, and Reset Iris clears it. Programmatic placement suppresses the resulting Moved events so startup cannot overwrite the saved frame.
- The bundle identifier is `com.iris.desktop` (reverse-DNS, never ending in `.app`). `tauri:dev` and `tauri:build:debug` merge `src-tauri/tauri.dev.conf.json`, which switches to `com.iris.desktopdev` so development data never touches the installed app. `core/legacy.rs` copies the old `com.iris.app` Application Support and WebKit folders on launch, before the runtime starts.
- Settings → General → Startup offers **Start at login** through `tauri-plugin-autostart` (a macOS LaunchAgent). The registration belongs to macOS, so the switch reads `isEnabled()` when the panel opens instead of persisting a flag in `settingsStore`; a failed write restores the previous state and reports inline. Development builds register as `Iris Dev`, so they never repoint the installed app's login item, and Reset Iris disables it in `reset_app_data` next to the other data it removes.
- Settings → Storage keeps two destructive actions separate: **Clear** removes conversations only, and **Reset Iris** (`reset_app_data`) wipes conversations, summary cache, speech audio, old identifier folders, settings, and the stored API key, then reloads both webviews. Clear goes through `clearStoredConversations`, which pauses the SQLite mirror and waits for pending writes so a hydrate cannot restore what was just deleted. Reset does **not** call `app.restart()`: that raced the single-instance plugin and could leave Iris with no window; `Storage::reset_schema` drops and immediately rebuilds the schema, and `reload_app_windows` reloads the main and overlay webviews. `Storage::clear` vacuums the database and truncates the WAL.
- Chat history lives only in SQLite via `src-tauri/src/core/storage.rs` (`iris.db` in the app data directory). Migration `002-search` adds external-content FTS5 tables (`conversations_fts`, `messages_fts`) with insert/update/delete triggers; `search_history` sanitizes input into quoted prefix terms and returns title hits plus message snippets with `\u0002`/`\u0003` match markers. The sidebar search debounces queries, groups message hits by conversation, and `focusMessage` pages backwards until a hit is loaded before Virtuoso scrolls to it. `useChatStorage` loads conversation summaries and mirrors changes incrementally (metadata upserts, per-message upserts, explicit deletes) after a short debounce; it never replaces a conversation with only the loaded page. `useConversationHistory` loads the newest 100 messages and fetches older pages on scroll-up; `react-virtuoso` renders only the visible window (with `historyStart` keeping prepended pages anchored) and the list fades at the bottom. The agent's `full_history` merges that request tail with the rest of the stored conversation, so pagination never truncates context. Focus reloads keep the overlay and history window in sync. The old `iris.chat` localStorage cache is imported once on launch and then removed; `iris.chat.ui` keeps only the selected conversation ids. The overlay's current quick conversation id lives in `app_meta` under `quick-conversation`; quick chats are ordinary UUID rows and their attachments are ordinary UUID folders. **Clear** emits `chat:cleared` so every window drops its in-memory copy.
- New conversations get a local fallback title immediately and then a short DeepSeek-generated title through `generate_conversation_title`. The title call runs in the background and can never block sending; it is applied only if the conversation still has its first user message and still carries the fallback title, so a manual rename or a New chat reset is never overwritten. The overlay header shows the same title as the sidebar (after `IRIS`, with a thin separator). **Previous conversation** (`⌘⇧N`) toggles `quickConversationId` back to the prior quick chat; if the current quick chat has messages, it stays in History, making the shortcut a back/forward toggle without moving any rows or files.
- The schema is owned by `src-tauri/src/core/migrations.rs` through `rusqlite_migration`, versioned in SQLite's `user_version`. Migration `003-app-meta` adds the small `app_meta` key/value table; it stores `quick-conversation`, the UUID the overlay is currently showing. Migration `004-message-summaries` adds the spoken-summary cache used by automatic read-aloud; it is keyed by assistant message id and kept in sync with message edits/deletes by triggers. Migration `005-selection-metadata` adds the source app, bundle id, pid, action, and selection stats for selection actions, keyed to the user message id. Migration `006-message-metadata` adds a JSON `metadata` column to `messages`; assistant replies store `{"ai_model":"..."}` for later model-performance analysis. `Storage::open` renames the old `iris:quick` row to a UUID and moves its attachment folder once; it is not a SQL migration because the new id is generated in Rust. **Migrations are append-only**: never edit or reorder a step that has shipped, add a new `<NNN>-<name>/up.sql` folder to `src-tauri/migrations`. Do not put `PRAGMA` statements in a migration (`journal_mode` is ignored inside a transaction, and `foreign_keys` is per-connection); `Storage::open` applies those outside. A pre-versioning database is adopted as version 1 in place (missing columns and tables are added, rows are preserved) — never dropped. `rusqlite_migration` must stay on the 1.x line while `rusqlite` is 0.32 — 2.x requires rusqlite 0.34 and a second rusqlite would make its `Connection` type incompatible with ours.
- Deleting a conversation sets `archivedAt` instead of removing it. Archived chats are read-only: they are listed under the collapsible **Archives** section at the bottom of the sidebar (only while non-empty), can be restored to the active list, or deleted permanently. Archiving an empty conversation deletes it instead of keeping a blank archive entry. `sendMessage` and rename ignore archived conversations, and the composer is replaced by `ArchivedComposer`. Archiving the quick chat keeps its content in the archive; the overlay creates a fresh UUID quick chat on its next hydrate.
- Automatic read-aloud is backend-owned: chat completion triggers `/v1/tools/tts`, then `afplay`. While `settingsStore.autoSpeak` and `summarizeSpeech` are both on, `core/agent.rs` appends `SPOKEN_SUMMARY_INSTRUCTION` to the system prompt and asks the model to end long (or code/table-heavy) answers with a hidden `<spoken_summary>` block; `read_aloud::SpokenSummaryFilter` streams only the visible answer, and `sys/speech.rs` uses the captured summary, caching it for later **Show summary** use, so the visible and stored message is never changed. Short answers skip the block. If it is missing or malformed, the existing `core/read_aloud.rs` summary call remains the fallback, and a failed summary falls back to the full text. Summaries are cached in SQLite's `message_summaries` table by assistant message id and reused, while the manual **Read aloud** button (`speak_text`) bypasses summarization and always reads the original reply. The history message footer's own `…` menu has a **Show summary** switch (`summaryStore`, fed by `load_spoken_summaries`) for replies with a cached summary; it swaps that message for its spoken version and routes its Copy/Read aloud through it, while other messages and the toggle's off state keep the original reply. Stop it on new messages, Cancel, New chat, and app exit. `speech:preparing`, `speech:start`, and `speech:end` carry the conversation id: the blob turns blue while the audio downloads, switches to the speaking animation with a blue wave during playback, and returns to green if TTS fails or finishes. The overlay still hides reply text until Show response. Only one reply is ever spoken: `sys/speech.rs` gives each request an epoch from `SpeechState::begin()`, so when two conversations both finish, the newest claim wins and the older download drops when it checks `is_current`. Keep that ordering — `stop()` bumps the epoch, so playback must call `interrupt()` (which does not) or it would cancel its own reservation. Completed replies also offer a manual **Read aloud** button (`speak_text`) in the overlay and on every assistant message in History; it speaks through the same endpoint and `speech:*` events. While that conversation is preparing or speaking, the button becomes **Stop** instead of restarting the same audio. Copy works on any completed reply and on user messages, read aloud works on completed replies, and Regenerate is limited to the newest reply. Editing the last user turn keeps the bubble at the rendered width and height and offers Copy alongside Save and Cancel.
- **Persistent memory** lives in SQLite's `memories` table (migration `007-memories`). When `settingsStore.memoryEnabled` is on (default), `core/memory.rs` waits 20 seconds after a completed reply, then asks DeepSeek for at most three durable facts using the newest exchange plus the current memories. Screen captures and attachment messages are excluded; pasted and selected text is allowed, and `message.metadata.pasted` is kept as provenance. Candidates are normalized, deduplicated, capped at 180 characters, and rejected by a deterministic sensitive-data filter (credentials, financial/health/government data, exact addresses, links/emails, prompt-injection markers). Updates insert a new current row and deactivate the old one through `superseded_by`, so the newest learned batch can be undone; user-edited rows are authoritative and paused rows stay paused when corrected. Active, unpaused memories are appended to both the island and main system prompts in `core/agent.rs`, capped at 30 items / 1,500 characters. Settings → Memory lists, searches, edits, pauses, deletes, clears, and undoes the newest learned batch. Turning learning off cancels pending runs. Clear conversations keeps memory; Reset Iris drops it and cancels pending memory tasks. The writer emits `memory:changed` so an open Settings panel refreshes.
- Read-aloud state lives in `src/stores/speechStore.ts` and is **not** scoped to a conversation. `useSpeechPlayback` subscribes to the speech events unfiltered (mount it once per window) because exactly one reply is spoken at a time. Filtering by conversation id used to leave `speaking` stuck when you switched chats, since the matching `speech:end` was ignored. `SpeechControl` renders beside the mic in both composers and nowhere else: the indicator and Stop stay in one predictable place instead of following the message. Its tooltip and the active `ReadAloudButton` show the configured stop shortcut (`⌘X` by default), and `useStopSpeakingShortcut` stops playback from either window.
- Screen Recording and Microphone permissions are declared in `src-tauri/Info.plist`; the overlay checks Screen Recording before capturing (`sys/screen.rs` + `src/tauri/commands/screen.ts`). If access is missing, the overlay shows a persistent notice with an **Open Settings** button that opens the Screen Recording pane directly; macOS only shows the TCC prompt once, and may require restarting Iris after granting. The quick overlay alone owns **screen capture**: `start_screen_capture` opens the full-screen `capture` panel at level 26 without taking a screenshot, so the screen keeps playing behind a live, transparent selection overlay, and re-shows the overlay passively above it at level 27 so Iris stays present and usable. There the user draws a region selection with eight resize handles, drags the toolbar's move icon directly to reposition the crop, and annotates it with Konva (pen, rectangle, arrow, four inks). `Cmd+Z` undoes the last stroke; the toolbar stays compact (28px tools, 16px inks). Attach (or Enter) hides the selection chrome, calls `capture_annotated_screen` (which hides Iris, captures the display including the annotation layer, then restores Iris passively), crops the selection at native resolution in the webview, and emits `capture:attached` as a JPEG that `useAttachments` adds to the overlay draft. While a capture is open, the overlay's capture button turns green; pressing it again closes the capture, discards the selection, and emits `capture:closed`. `close_screen_capture` restores the overlay. All AppKit window calls must run on the main thread; only the final `screencapture` runs on a blocking task. The capture UI lives in `src/capture.tsx` and is not part of the history window. The separate `⌘⇧A` ask path skips that UI entirely: it hides Iris, captures the display under the mouse with `screencapture -t jpg`, restores the overlay, and emits `capture:attached` so the prompt is focused with the screenshot already attached. Permission prompts use the shared `PermissionNotice` component; use it for any future permission that needs Open Settings and dismiss controls, rather than a one-off error panel.
