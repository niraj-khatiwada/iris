# Taste
- Expects system appearance (macOS light/dark) to drive UI theming — the overlay should follow the OS setting, not the in-app theme selector, which he calls out as a distinct thing. Confidence: 0.6
- Prefers compact UI controls (smaller heights, tighter padding/gaps, smaller type and icons) over large, spacious ones; flags oversized nav buttons/sidebar items as "too large." Buttons should *always* use the small size variant (`size="sm"`) rather than the default, and adjacent buttons must match each other in size *and* visual style — a same-size pair with mismatched variant/fill (flat vs. filled) still reads as "two different sizes" to him and gets sent back. Confidence: 0.8
- New keyboard shortcuts must be user-customizable, registered in the Settings → Shortcuts section alongside existing ones, not hardcoded defaults. Confidence: 0.6
- Names features by their literal function and corrects mislabeled terminology ("voice means microphone" — not voiceover/read-aloud); labels in settings and docs should match what the control actually does. Confidence: 0.55
- Dictation/voice input must compose with the existing draft rather than replace it: typed text, attached images, and the transcript should all be sent together as one message. Confidence: 0.6
- Expects single-instance semantics for audio playback: never allow two read-alouds to overlap — starting a newer one must supersede/stop the previous one, so the latest request always wins. Confidence: 0.6
- Dictates exact ordering of composer controls: the mic button stays rightmost, with the read-aloud indicator/stop to its left — corrects placement by specifying left/right position. Confidence: 0.5
- Prefers app-level, single-location controls for ongoing cross-cutting state (e.g. read-aloud wave + stop beside the mic in the chat input) rather than inline controls attached to the message that started it — wants one predictable, central place rather than a per-message indicator that follows context. Confidence: 0.55
- External API behavior (endpoints, paths, auth header shapes) must be verified against the live service before being reported as working — he rejects guessed URLs and "it passes" claims that were never exercised end-to-end, and expects the agent to say plainly when something couldn't be verified. Confidence: 0.7
- Secrets (API keys) must be stored in the OS keychain, and must be write-only in the UI: once set, the app must never display or read the key back in settings — only indicate that one is saved (a plain "API key is set" plus Replace/Remove is enough; a last-four hint is optional). Opening a settings panel must never trigger an OS credential-store access prompt just to render status; touch the keychain only on explicit Replace/Remove, and determine "already set" from a non-prompting presence check of the real store — never infer it from a locally cached hint, since a missing cache must not make a configured app look unconfigured and show the entry field again. Confidence: 0.8
- Stored credentials must have an explicit remove/revoke action in the UI, so the user can delete a stored key without resetting the whole app. Confidence: 0.6
- Inline status/error text for a form field belongs directly below that input, left-aligned with it — never tucked into the adjacent button's column, where it wraps into a narrow block and distorts the row height. Confidence: 0.65
- No hardcoded provider-specific URL path segments in request code (`/anthropic`, `/v1/tools/asr`, etc.): paths must derive from a user-configurable base URL, and auxiliary endpoints (speech/TTS, transcription/ASR) should be full, editable URLs surfaced in Settings; he treats any baked-in provider route as a bug and asks for it to be removed. Auxiliary endpoint defaults should be templates that inherit the configured base URL via a `{{base_url}}`-style placeholder (e.g. `{{base_url}}/v1/tools/tts`), with the field description telling the user the placeholder exists. Confidence: 0.8
- The app must stay AI-provider-agnostic: user-facing labels and error strings never name a specific vendor (no "DeepSeek" in settings categories, search terms, placeholders, or messages — just "Add your API key in Settings"), and provider-branded feature names are replaced with generic ones ("Thinking mode", not "DeepThink"), since other providers (OpenAI, others) will be added. Confidence: 0.8
- User selections persisted in storage (e.g. the chosen model) must survive any refresh/refetch of the underlying list: automatic defaulting to the first result happens only when nothing is stored yet, and an existing saved preference is never overwritten — a Refresh button updates the list, it does not reset the choice. Confidence: 0.75
- Wants the accent color kept out of text: green is reserved as a status/identity signal (the AI blob, success icons, transient confirmations), never applied to copy like button labels or message text — accent-tinted surfaces are fine, accent-tinted words are not. Confidence: 0.55
